## 0. Purpose and plan context

| phase | what | status |
|---|---|---|
| 0–3 | Frozen evaluation and bar; acquisition; CNN round 1; pretraining ablation | done: every CNN level with the bar (GBT_ship 0.510), none above it |
| **2X** | **Exploratory CNN redevelopment, bounded and fully reported** | **step 1: this directive builds the inputs** |
| 4 | Pre-registered freeze and one confirmatory scoring | later |

**Why this is needed.** Every CNN so far has seen a 256 × 256 AUV-pixel window, which holds only about 2–9 ship cells
across. The exploratory phase will test a CNN that reads the ship grid directly over a much wider area (tens of ship
cells, several kilometres), against a GBT given features over the same wide area.

That needs ship data **beyond the AUV footprint**. Each pair's harmonized `lr.tif` is clipped to the pair's footprint
(`harmonize.py:122-123`, `rio.clip(drop=True)`), so it contains no context. This directive builds, for every
development pair, a **context grid**: the pair's own LR source, gridded by the development chain over the footprint
plus a 5 km buffer, on a lattice aligned with `lr.tif`, with contract v2.1 ship products on the same grid.

**What must hold:**
1. **Same source as `lr.tif`.** The context grid uses only the LR cruise(s) or provider product that produced the
   pair's `lr.tif`. No other cruise, no composite, nothing HR-derived.
2. **Same representation.** The development gridding chain (ACQ-R04 §5.1), on a lattice that shares `lr.tif`'s pixel
   size and origin.
3. **Verifiable agreement inside the footprint** with `lr.tif` (§3).
4. **Sealed units untouched.** Confirmatory and lockbox pairs get context grids only at Phase 4, from the code frozen
   here.

**Scope discipline.** Do the items below and nothing else. If a result suggests a new analysis, list it in one line under
"Not pursued". Do not run it.

**Challenge clause.** Report any wrong or underspecified instruction in §1 of the report, with evidence. Items that are
Steve's call become HOLDs (at most 3).

## 1. Context extent and lattice

For each pair:

1. **Extent:** the pair's `footprint.geojson` buffered by **5,000 m** in `lr.tif`'s UTM CRS, then its bounding box.
   - 5 km keeps every context grid inside the 10 km pretraining exclusion zone, so no context cell overlaps a pretraining
     block.
   - It also leaves room for a 64-cell window at cells up to about 150 m.
2. **Lattice:** the same CRS and pixel size as `lr.tif`, with the origin on `lr.tif`'s lattice (the context transform
   differs from `lr.tif`'s only by an integer number of pixels). Record the pixel offset of `lr.tif` inside the context
   grid.

## 2. Building the context grid

### 2.1 NCEI-swath pairs (development chain)

1. **Source files.** The pair's LR cruise(s) as recorded in the manifest (`lr_cruise`, `lr_doi`).
   - **Whole-cruise fetches:** the files already on OAK.
   - **Subset fetches** (A.5 nav-intersection: FK181031, NA080, TN299, TN399 and any other recorded in the plans):
     identify every file of that cruise with soundings within the context extent, using the ACQ-R04 per-0.1°-cell file
     selection. Fetch only the missing ones to OAK `raw_lr_swath/<cruise>/`, using the ACQ-R04 collision-safe naming,
     byte-exact checks and sha256. Update that cruise's fetch manifest.
2. **Geographic grid.** Run stage-C `mbgrid` with the development recipe (`-A2 -G3 -F1 -C0 -M`, the same `-E` spacing
   formula and cell) over the context extent ± 1 km. Snap the region so that its node lattice coincides with the lattice
   stage C used for the pair: same dx, dy and origin modulo dx, dy. Record how the original lattice was recovered.
3. **Warp** to the context lattice of §1 with the development warp (bilinear, nodata −9999), then convert to float32
   with NaN as nodata.
4. **Write** `ctx_lr.tif` and `ctx_lr_valid.tif` (finite cells).

### 2.2 Provider-grid pairs (DISCOL, CCZ, TAG, Cal DIG)

- **Source:** the same provider grid that produced `lr.tif` (OAK `raw/`), reprojected to the context lattice by the
  same harmonize path that produced `lr.tif`, without the footprint clip.
- **Coverage:** where the provider grid does not cover the buffer, the context grid is NaN there. **Do not grid
  their raw EM122 to fill it.**

### 2.3 Ship products on the context grid

- **NCEI-swath pairs:** run the contract v2.1 builder unchanged with `ctx_lr.tif` in the role of `lr.tif`, using the
  §2.1 source files. Write `ship_products_v2_1/` and `products.json` with QA, inside the context directory.
- **Provider-grid pairs:** follow the existing rulings. Cal DIG has no swath (products unavailable). CCZ, DISCOL and TAG
  are masked (ruling R4): write `products.json` with `available: false` and the reason, and no rasters.
- **EX1402L2:** carries the R05 consumer-side override (`ship_xtrack_frac` unavailable). Record it in `context.json`;
  do not rebuild that pair's acquisition products.

### 2.4 Output per pair

`<pair harmonized dir>/context_v1/` (resolved from the manifest), with:
- `ctx_lr.tif`, `ctx_lr_valid.tif`;
- `ship_products_v2_1/`;
- `context.json`: source files with sha256, commands, lattice, the `lr.tif` pixel offset, buffer, coverage statistics,
  the §3 agreement statistics, and the code commit.

Existing harmonized files are not modified.

## 3. Agreement with `lr.tif` inside the footprint (required)

For each pair, on `lr.tif`'s valid cells, compare `ctx_lr.tif` (the cells at the recorded pixel offset) with `lr.tif`.
Report:
- n cells;
- median difference;
- RMS and robust σ (1.4826 × MAD) of the difference;
- each of those divided by the pair's median `s_lr` (from R04's tile tables if available to this repo; otherwise the SD
  of `lr.tif` in 128-px windows, stated);
- the fraction of cells with |difference| > 0.1 × median `s_lr`.

**Expected:** identical for provider-grid pairs. For NCEI-swath pairs, identical if the original lattice and file set
were reproduced; otherwise small. R03 measured about 1 m RMS between re-gridding and `lr.tif`.

**Gate:** flag `ctx_disagrees` when robust σ of the difference exceeds 0.10 × median `s_lr` or the median difference
exceeds 0.5 m. Flagged pairs stay in the output. Report them as a HOLD with the statistics. Do not tune the gridding to
remove a flag.

**Products:** for NCEI-swath pairs, compare `ship_count` and `ship_rsd` of the context products with the existing
`ship_products_v2_1/` on the cells of `lr.tif`, using the same statistics. Report them; no gate.

## 4. Coverage report (for the CNN repo's window choice)

For each pair and for each window size **W ∈ {16, 32, 64} ship cells** (W × W cells of the context lattice, centred on
the centre of each `tiles_v1.1` tile of the pair):
- the fraction of tiles whose W-window has ≥ 50 % valid `ctx_lr` cells;
- the median fraction of valid cells per window;
- the window's ground size in km (W × cell).

Read `tiles_v1_1.parquet` (CNN repo, tag `phase0-freeze`) read-only for the tile centres, and verify its sha256 against
R05 §6. Report per pair and per unit. This is a data-availability statistic only. Nothing is scored.
