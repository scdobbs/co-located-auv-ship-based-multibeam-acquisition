## Part A: script changes

Edit only `src/phase4/` and, if needed, the guard. No chain file is edited. For every changed file, report the sha256
before and after and a one-line summary of the diff.

### A1. Prior values for June-vintage sealed pairs

- A pair takes prior values if and only if its manifest v2.1 `designation` is `lockbox`. This is data-driven, not a
  hard-coded pair list.
- Prior values: `hr_native_res_m` and `lr_native_res_m` from the manifest row; `max_recoverable_k` and its verdicts
  from the June sweep record. Record the source of each value in the step record.
- **Consistency check from records:** the June sweep record's lr_native for each lockbox pair must equal the manifest
  row's lr_native at the manifest's precision. If not, stop (rule C4) with both values.
- No C2a computation and no sweep are run for such a pair.

### A2. Lockbox fetch

- **Trigger (data-driven):** fetch a pair's LR cruise if and only if its directory is absent from OAK `raw_lr_swath/`
  and the June plan lists it. In `phase4` mode, assert that the triggered set is exactly {AT42-03, TN159}. Any other
  set stops the run before any fetch, as a lock.
- **Fetch:** the existing `fetch_swath.py --plan-csv` path, unchanged, from the June plan: swath files only, the June
  whole / subset mode, byte-exact against `Content-Length`, `gzip -t`, sha256 per file, files 0444, per-cruise
  `fetch_manifest.json` and `SHA256SUMS`, at most 6 workers, back-off on 429 / 503.
- **On failure** (any file missing after the fetcher's own retries): that pair's products are written as unavailable
  with reason `lockbox fetch incomplete (<n> of <m> files)`, `ship_products_usable = false`, and the run continues.
  This applies to lockbox pairs only. For a confirmatory pair a missing swath directory stays a stop (rule C4).
- **Confirmatory swath:** never fetched. Assert that each confirmatory cruise directory holds exactly its
  fetch-manifest count (28, 107, 222), as ACQ-R06 found.

### A3. Write path into sealed directories

1. **From code and records only**, report what permissions the ACQ-R02 chain set on `harmonized_confirmatory/<unit>/`,
   on the pair directories inside it, and on their files (the code that sets them, with file and line), and what is
   recorded for the two lockbox directories under `harmonized/`. Do not stat or list a sealed path.
2. **Implement, for `phase4` mode, after the allowance:** for each pair directory the step writes into, record its mode
   bits, add owner write permission to that directory only, write `ship_products_v2_1/`, `step1_record.json` and
   `sweep_record.json`, set the new files and subdirectory to 0444, then restore the directory's recorded mode.
   Record every mode before and after in the step record. Existing files are never opened for writing.
3. If the write or the restore fails, stop (rule C4) before the supplement is written, and report the modes found.

### A4. Per-k verdicts in the run record

For every pair, the run record carries the per-k verdicts (from the sweep, or from the June record for prior-value
pairs) and the source of k. No curve values are recorded or printed.
