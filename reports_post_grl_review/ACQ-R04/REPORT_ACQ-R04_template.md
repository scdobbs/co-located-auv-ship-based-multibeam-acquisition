### 1.1 Challenge findings from §1–§2 (accepted by steering 2026-10-03; recorded as implemented)

1. **Extra exclusion geometries.**
   - **What:** every ACQ-R02 `hr_footprints.gpkg` polygon was also excluded at 10 km: the full multi-dive releases, pu00, pu03 and verification rejects.
   - **Effect:** 87 more cruises excluded (`exclusion_v1.json:counts.excluded_only_by_extra_gpkg`).
2. **Buffer projection.**
   - **Problem:** EPSG:6933 is not distance-true; at 60° latitude a "10 km" buffer covers about 5.8 km north–south.
   - **What was done:** distances measured in local azimuthal-equidistant projections on ≤ 2° pieces. The cached NCEI footprints are simplified at 0.01°, so cruise-level tests add 1.113 km (16 cruises excluded only via this tolerance, `counts.spatial_only_via_tolerance`).
   - **Block level:** the guard uses exactly 10 km in the block's UTM.
3. **ACQ-R01's 3,210 counted records, not cruises.** It is 3,016 unique cruises.
   - **Newly excluded (153):** cruises near pairs added since ACQ-R01, the extra polygons and the 50 km lockbox radius.
   - **Newly included (105):** excluded by ACQ-R01 only because of §3 candidates that never became units (`tables/r01_diff_*.md`).
4. **"Floor of 15 per family, rest proportional"** is ambiguous. Applied as 15 + a proportional share of the remaining 295. **"Over-represented stratum"** (size cap) is undefined; applied as "share of bytes > share of cruises" (`selection_v1.json`).
5. *(item 5, development gridding representation, was not accepted: replaced by ruling 1; see §5.1.)*
6. **Depth "where known"** comes only from the ACQ-R01 sample (107 cruises). The `.inf` files sit in NCEI `generated/` directories, which the crawl does not walk (slow, no swath) (`pool_crawl_summary.json:depth_known`).
7. **Silent listing failures.** The stage-A/B walker (`iter_cruise_files`) skipped any subdirectory it could not list. The ACQ-R04 crawl retries 3 times and records failures; 1 cruise is `listing_incomplete` and was not selectable (`pool_crawl_summary.json`).

### 1.2 Challenge findings raised during the run (with evidence)

1. **File-name collisions across NCEI sonar subdirectories.**
   - **Problem:** multi-sonar cruises serve the same file name from several directories, e.g. `MB/em710/9999.all.mb58.gz` and `MB/em122/9999.all.mb58.gz`. A flat raw directory keeps only one.
   - **Pretraining run:** 11 of the 400 selected cruises affected. Fixed by storing colliding names as `<subdir>__<name>`; AR30-01 was re-fetched and re-gridded.
   - **Development data:** the read-only audit found one development cruise, AR26. Its `lr.tif` (stage C) used the em710 copy, while products v1/v2/v2.1 used the em122 copy.
   - **AR26 resolved:** re-fetching both copies showed the em710 copy has **0 soundings** in the AR26__MGDS_31838 product window (its 156,986 good beams lie at 32.86° N, 79.96° W). The em122 copy is empty. No development data lost soundings. The OAK fetch manifest was corrected and ledgered.
   - **June misdiagnosis:** the stage-B recovery report called the 1,275 B HEAD a "transient NCEI glitch"; it was this collision (`name_collision_audit.json`, `ar26_check.json`, `ar26_check_mbinfo.json`, `ar26_manifest_correction.json`).
2. **Container sandbox on `$GROUP_HOME`: a Sherlock storage-rule breach (now fixed).**
   - **Problem:** every Apptainer start read the 3.6 GB / 109,665-file MB-System sandbox from Isilon NFS. That is "dozens of simultaneous jobs each doing modest I/O" on `$GROUP_HOME`, which Sherlock's storage rule forbids.
   - **Fix:** the run was stopped on 2026-10-05. The sandbox is now packed once to `$GROUP_SCRATCH` (`containers/mbsystem_sandbox.tar`, sha256 `ec8c3f17…`), copied to node-local disk per job and verified.
   - **Effect:** container starts 0.75 s locally against 6.8 s from NFS; results identical (`prelaunch_checks.json`; commit 4f161bb).
3. **Container overload and leaks on shared nodes.**
   - **Problem:** up to 9 of my tasks landed on one 128-core serc node, with 192 `fuse-overlayfs` processes. Timeouts killed only the `apptainer` parent, so hung containers piled up and 72 of 97 tasks sat in 3 h mbgrid timeouts.
   - **Fixes:** every MB-System call now runs in its own process group and is killed as a group on timeout, with a bounded reap. A node runner caps containers per node (commit d41c047).
   - **ACQ-R03 lesson, now in code:** at most ~6 containers starting at once per node.
4. **Per-block file selection by whole-file bounding box.**
   - **Problem:** long transit files were listed for every block, so mbgrid re-read tens of GB per block. Six cruises sat 18+ h in 3 h batch timeouts.
   - **Fix:** select files by the 0.1° cells each file actually has soundings in, and cap batches at 16 blocks. TN358 then finished in 1.1 h (commit debad9d).
   - **Earlier cruises unaffected:** the old rule chose a superset of files, and files without soundings in a block's region contribute nothing.
5. **The contract v2.1 builder (unchanged) cannot build products for antimeridian blocks.**
   - **Cause:** `lr_window` wraps (west > east), so `mblist` returns no soundings. The QA function then returns before writing `qa_shift_surface.csv`, and `build()` crashes on `chmod` of that file (FileNotFoundError).
   - **Scale:** 62 blocks (`failure_ledger_v1.csv:stage=products_failed`). Their grids are correct; products are recorded as failed and unusable.
   - **Correction:** the 4 NBP0402 blocks first attributed to scratch I/O are of this kind.
6. **Unreadable files (ruling option 2).**
   - **Rule:** a file that `mblist` rejects on every attempt whose container ran to completion (at least 3 such attempts) is left out and ledgered (`unreadable_skipped`). A cruise still fails if the container failed or no file is readable.
   - **Count:** 61 files (EX2205: 60 EM304 GSF files, rejected 5/5 clean attempts; KRY09_02: 1).
7. **Argument-length and parser bugs (fixed).**
   - **Argument length:** one argv string is capped at 128 KB (RB-20-02: "Argument list too long"); scripts are now written to files.
   - **Parser:** `#ERR` markers could be glued to a partial `mblist` line (EX2205), and a non-numeric token broke float parsing (KN199-02). Markers now start on a fresh line; non-numeric lines are dropped and counted.
   - **Affected cruises:** all re-run.

## 5. §3 Fetch, grid, products

### 5.1 Development gridding chain (ruling 2026-10-03)

The development `lr.tif` was produced by:
1. **Geographic stage-C mbgrid:** `-R` = region ± 1 km; `-E dx/dy/degrees` with `dx = cell/(111320·max(0.2, cos mid-lat))`, `dy = cell/111320`; `-A2 -G3 -F1 -C0 -M`. Source: `src/discovery/stage_c_full.py:181-190`, and `src/acq_r01/grid_lr.py` (main).
2. **`.grd` → GeoTIFF** with the grd's CRS and nodata (`stage_f_harmonize._lr_to_tif:50-67`, `harmonize_new.lr_to_tif:184-193`).
3. **`harmonize._open`/`_reproject`** (`src/harmonize.py:53-63`): to the local UTM, **bilinear**, nodata −9999, **GDAL default output grid** (no explicit resolution).
4. **`rio.clip(drop=True, all_touched=False)`** (`harmonize.py:122-123`).

Verified: GDAL's default warp of each union `.grd` reproduces the persisted `lr.tif` pixel size and alignment exactly on all 8 ACQ-R02 development pairs (transcript check, 2026-10-03).

Blocks use the same chain (`blocks.GRID_MODE = "dev_chain"`; recorded in every `block.json:gridding_chain`).
