**Context lattice (§1):** `footprint.geojson` buffered by 5,000 m in lr.tif's CRS, bounding box snapped outward to lr.tif's pixel lattice (`lattice.context_lattice`); the context transform differs from lr.tif's by the integer pixel offset recorded in `context.json:lr_pixel_offset_in_context`.

**Stage-C lattice recovery (§2.1.2) — CONFIRMED {{json:tables.json:lattice_verified}}/{{json:tables.json:n_ncei}}.** The development `lr.tif` of an NCEI pair is the GDAL-default bilinear warp of a geographic `mbgrid` grid (ACQ-R04 §5.1). The context grid must be gridded on a lattice that coincides with that grid's node lattice. The June grids were purged from scratch (2026-09-20), so the lattices were recovered (`lattice.source_lattice`) and verified (`lattice.verify_lattice`): GDAL's default warp output of the recovered lattice (`rasterio.warp.calculate_default_transform`, the grid `harmonize._reproject` uses) must reproduce lr.tif's pixel size (< 1e-9 relative) and put lr.tif's origin at an integer pixel offset (< 1e-6 px). mbgrid's dimension rule used for the recovery was itself verified on all 18 ACQ-R02 union grids on OAK: bounds kept exactly, node count = round(span/spacing + 1), spacing = span/(n − 1).

{{table:lattice_recovery}}

The context mbgrid region (`lattice.geo_region_for_context`): the context box in lon/lat (segmentized) ± 1 km, snapped outward to the recovered node lattice (same dx, dy; origin modulo dx, dy; node offsets recorded in `context.json:gridding.mbgrid_region.node_offset_from_source`); the produced grid's lattice is checked against the plan after every mbgrid call (`grd_lattice_check`).
