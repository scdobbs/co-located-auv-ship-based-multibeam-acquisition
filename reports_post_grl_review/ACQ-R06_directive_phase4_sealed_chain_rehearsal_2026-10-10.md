## Part A: the entry script

Write `src/phase4/sealed_step1.py`. It calls the existing chain code unchanged. If an existing function cannot be
called for one pair without editing it, write a thin wrapper and report it under the challenge clause.

**Per pair, in this order:**

1. Read the pair's harmonized `hr.tif`, `lr.tif` and masks. No re-gridding, no re-harmonization, no new
   co-registration. The recorded co-registration and `qa_status` stand.
2. `hr_native_res_m` and `lr_native_res_m` by the C2a rule, exactly as the ACQ-R02 chain computes them for a new pair.
3. The C2c sweep (`sweep_pair`) at that `lr_native`, giving `max_recoverable_k` and `k_sweep_status`. For a pair whose
   manifest row already holds a k (the two lockbox pairs), the manifest value is kept and no sweep is run.
4. If the pair has a k: contract-v2.1 ship products on the grid of `lr.tif`, with `products.json` and its QA.
   A pair with no k gets no products.
5. `ship_products_usable` by the rule of §C1.
6. One row for the supplement, with the manifest v2.1 columns.

**Not computed, in either mode:** QC figures, HR-minus-LR difference maps or statistics, cross-checks against other
grids, context grids, tiles, targets.

**Outputs:** the products and the sweep record go into the pair's own harmonized directory. The supplement is
`manifest/pairs_phase4_sealed.parquet` (phase4 mode) or `ACQ-R06/rehearsal/supplement_rehearsal.parquet` (rehearsal).
The script prints and reports per pair only: the two spacings, k, sweep status, products available or not, flags, and
usable or not. It never prints a sweep curve.

**Modes.** `--mode rehearsal` or `--mode phase4`.

- `rehearsal`: the guard is fully on, the pair list is restricted to development pairs, and outputs go to a scratch
  root. Existing development files on OAK are never overwritten.
- `phase4`: the only mode that admits the five sealed pairs. **Do not run it in this directive.**

The two modes must differ only in the pair list, the guard allow-list and the output root. List every place where the
code branches on mode, with line references.

**Locks in `phase4` mode:**
1. A sign-off file must exist and hold the sha256 of the tagged pre-registration (path and expected hash given as
   arguments).
2. The sha256 of this script and of every repo file it imports must match `freeze_record.json` (Part D).
3. The pair list must be exactly the five pairs of §0.3.
4. If `manifest/pairs_phase4_sealed.parquet` already exists, the script refuses. There is one run.

**Refusal tests.** With the guard installed underneath, show that phase4 mode refuses: without the sign-off; with a
wrong pre-registration hash; with a changed code file; with a development pair in the list; with a missing sealed
pair; and when the supplement exists. Use dummy files. Report each test with the exception raised.

## Part C: fixed rules for sealed pairs

Rulings cannot be made on a sealed pair once scoring is in sight. These rules replace them. Implement them in the
script, check them against development, and report the checks.

### C1. Ship-product usability

`ship_products_usable = true` if and only if the products were built (`available: true`) and `products.json` carries
none of the contract-v2.1 flags (`registration_shift`, `vertical_offset`, `insufficient_overlap`). Otherwise it is
`false`, with the reason recorded. The pair stays in. The CNN repo masks the product features of an unusable pair, as
it does for the flagged development pairs.

**Check:** apply the rule to all 45 development rows of manifest v2.1 and compare with the recorded
`ship_products_usable`. Report the count that agree and list any that do not, with their `ruling_source`.

### C2. Builder failure

If the product builder fails on a pair for a reason tied to the data (an unsupported sonar format, no soundings in the
window, a field the format does not carry), the products are `available: false` with the reason, and the pair stays in
with `ship_products_usable = false`. The script continues with the next pair.

### C3. No k

A pair whose sweep returns no recoverable k gets `max_recoverable_k` empty and its `k_sweep_status` as returned. Nothing
else is built for it. It is "not scorable (no k)" downstream.

### C4. Anything else stops the run

Any other error stops the script before the supplement is written. Nothing is retried with changed code or settings.
It is reported as a HOLD.
