# M3.1 — v1.4.1 fix pass (footprint, dedupe, platform, enrichment, re-score)

v1.4.1 applied to the M3 catalogs without re-harvesting. Read-only / append-only
preserved against the manifest and all harmonized rasters.

## §1 — True HR footprint geometry

- **Seeds:** `src/discovery/seeds.py:_footprint_from_raster` now walks the valid-pixel
  mask of the harmonized HR raster (rasterio + `rasterio.features.shapes`)
  instead of the bbox. All 21 manifest seeds (DISCOL, 18 Cal DIG, CCZ, TAG) had
  their geometries replaced with their true valid-data polygons.
- **MGDS:** the per-file `bounds` is still what the FileServer publishes; we
  cannot compute valid-data extents without downloading the grids. Per the
  directive's "flag, don't drop" guidance:
  `footprint_suspect = True` when `is_auv_grid AND footprint_km2 > 60 km²`
  (relaxed to 300 km² for grids coarser than 4 m).
  - **48 of 132 HR are footprint_suspect** (37 %) — they're kept in the catalog
    but held out of the triage tier.

## §2 — De-dupe survey families

- `src/discovery/dedupe.py`: greedy clustering on (platform_norm, native_res
  rounded to 0.01 m). Pairs are merged when footprint IoU ≥ 0.90 OR consecutive
  DOI integers (window 5) with IoU ≥ 0.50.
- **159 → 132 HR records** (27 sibling rows collapsed). Examples in the log:
  - MGDS:32556/57/58 (consecutive 1 m MBARI grids at the same Axial site) → one canonical row
  - MGDS:30217/18/19 (Sentry 1 m siblings) → one canonical row
  - Loihi Sentry, several others.
- Surviving rows record `sibling_hr_ids` and `sibling_dois` so nothing is lost.

## §3 — Tighter AUV platform filter

- `src/discovery/platform_filter.py:classify` → `(is_auv_grid, platform_verdict, platform_reason)`.
- Recognised AUV names (MBARI Mapping AUV / Sentry / ABE / REMUS / ABYSS / AsterX / …)
  always pass; resolution > 4 m on an "AUV" entry → demoted to `ambiguous`.
- `R/V *` platforms with no AUV sonar → `surface_vessel`; with an AUV sonar
  → kept as `auv` (the host-vessel case; e.g. AUV-on-Rachel-Carson).
- Result: **129 auv / 3 ambiguous / 0 surface_vessel** in the kept HR set
  (R/V Zephyr / Falkor / Atlantis / Thompson / Rachel Carson hull entries excluded).

## §4 — LR `lr_native_res_est_m` enrichment

- `src/discovery/geoportal.py`:
  - Tries the NCEI Geoportal ISO endpoint (`gov.noaa.ngdc.mgg.multibeam:<CRUISE>_Multibeam`); cached per cruise.
  - Fallback: sonar+depth lookup table (EM122 deep ~50 m, EM710 shallow ~10 m, EM2040 ~3 m, …).
  - Records `lr_res_source ∈ {geoportal, estimated, unknown}`.
- **1,408 of 2,541 pairs** (55 %) have populated `res_ratio`.
- `lr_res_source` distribution across pairs: 1,986 estimated / 555 unknown
  (Geoportal direct hits are rare; the bulk are sonar/depth heuristics).
- Ratio quartiles: min 3.6 / p25 25 / median 46 / p75 60 / max 207. Many sit
  above 30× → the high_ratio demotion in the score fires, but they're still
  in the catalog as informational entries.

## §5 — Re-scored + triage view collapse

- New score (in `src/discovery/join.py:_score`):
  - **4.0 × overlap_frac_hr** (now meaningful)
  - **+2.5** for ratio in the 5–25× super-resolution sweet spot
  - **+1.0** processed grid; **+0.5** province gap (vent/seamount/nodule/abyssal)
  - **−1.0** ratio > 40×; **−1.5** ratio < 1.5×; **−1.5** footprint_suspect; **−0.5** needs_check
  - Raw overlap area is a 0.3× log tiebreaker only
- **Triage view** (`candidate_pairs.gpkg` layer `triage`): one best LR per HR,
  filtered to AUV grids that pass the platform filter and aren't footprint_suspect.
  - **78 rows** (down from 3,033 in the M3 catalog) — one per distinct AUV site.

## Hard rules (unchanged)

- Read-only / append-only against existing work. `manifest/pairs.parquet`,
  `$DATA_ROOT/{raw,harmonized}/`, and all Tier 1 + Tier 2 pairs are untouched.
- APIs only. Joins on real boundary polygons (manifest seeds via valid-data
  mask; MGDS via per-file bbox union with `footprint_suspect` flag where the
  envelope is implausible).
- No composite LR pairings.
